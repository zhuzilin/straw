# straw implementation and proof correspondence

[中文版](VERIFICATION_BOUNDARIES_zh.md)

This is a call-chain review index, not a completed refinement proof. A partial
`View` does not cover the enclosing object; a helper postcondition does not prove
its caller's postcondition.
[Formal verification](FORMAL_VERIFICATION.md) distinguishes proofs, finite model
checks and execution evidence.

For 0.1.4, new proof work is frozen. Remaining correspondence and liveness
obligations are deferred, with the release's regression coverage listed in
[the scope matrix](FORMAL_VERIFICATION.md#verification-scope-for-this-release).
The existing proof gates remain required. Stage-specific evidence below keeps
its recorded input scope; it is not a claim about a newer build.

`catalog_decode::decode` now connects the actual wire decoder and semantic predicates to complete ordered operations. Its View uses a fixed namespace map and semantic operation sequence; `catalog_frame::Decoder` now establishes raw payload/run-to-operation meaning under the parser relation and Resolver/KeySet contracts, and Target preserves that business history. `LogState::new` establishes empty interpretation and `catalog_append` binds input/run/serialization to appended history. Independent parsed Values now have a conditional unique completed catalog interpretation via catalog_json_equivalence/catalog_equivalence; native Resolver/KeySet conformance and full transaction composition remain open. The HashMap consuming iterator uses a separately audited two-primitive library contract. See the [construction scope](FORMAL_VERIFICATION.md#catalog-fields-to-ordered-operations).

`protocol::execute_commit` is the actual four-effect dispatcher, with quarantine armed before apply and removed only after successful return. Its per-transaction View and lower-effect contracts are separate from native `CommitIo`, complete root extraction and full coordinator replay. Caught-unwind behavior has a native data-loss regression and finite `CommitApplication` model; Verus does not prove unwinding itself.

External trusted boundaries include byte I/O, sync and lock semantics, hash
authentication, and deployment fencing. SHA and serde implementations are outside
the proof. The `exclusive_owner` string records a caller assertion; it is not a
fencing mechanism.

Caller responsibilities are concrete: `Journal::{append,recover}` and
`Catalog::{append_frame,refresh_with_sync}` supply the framing slices/digests and
frame offsets; `Indexes::{roots,candidates}` prove the actual catalog snapshot;
`gc_batch::collect` proves parent coverage; actual `gc_io` proves unlink and parent-barrier dispatch, and `directory_io` proves the complete ordered barrier loop. Native `BatchIo` must still bind targets/paths/handles and the complete ancestor chain to those effects; `closure_inner` and
`consume_with_receipt` supply traversal edges; actual commit dispatch is proved
under `CommitEffects`, whose native implementation remains open; catalog replay arms rebuild before tentative changes; actual append_to connects confirmation to successful Writer synchronization. These call sites are
identified by source review and regressions, not yet proved as complete callers.
The framing byte bodies and their encode/decode composition are now verified;
The shared recovery driver also proves SHA input spans and byte-prefix behavior. Concrete file identity, JSON business semantics and full caller composition remain obligations.
In particular, `serialized_catalog_history` still assumes straw's missing Catalog
refinement; an external lock grant does not establish it.

Using the correct descriptor, interpreting results, preserving uncertain effects,
establishing complete logical roots and binding snapshots to durable prefixes, arming rebuild before partial mutation, and
establishing downstream preconditions are **straw implementation obligations**.
Unproved portions remain open even when an upper-level model assumes them.

Applications may retain readers/checkpoints forever. Safety then requires
preservation. Reclamation progress applies to sealed objects that become
permanently unowned, with continued collection, the required task fairness and
eventual operation completion. Filesystem recovery cannot imply application release.

Close a correspondence only with the actual source body and View, model action
and invariant, caller-established premises, success/error postconditions, and
remaining trusted interfaces. Verus must check the actual body. Model checks and
fault regressions supplement that proof; they do not replace it. Preserve exact
input hashes and recheck affected proofs after source changes.

The shared byte recovery body also proves exact malformed reasons and valid-log completeness: an accepted payload history is a unique prefix, and success reaches the complete legal history. The negative controls include spurious rejection and misclassified I/O errors. These properties do not discharge native Device/Target or JSON-to-business-state obligations.

The actual catalog `catalog_frame::Decoder`, `catalog_decode::decode` and Target connect parsing/run checks, field/semantic admission and ordered business operations to the raw history. Actual append input/run/serialization binding now establishes the other side of that history invariant. catalog_equivalence proves unique six-index state/cursor/sequence for the same raw prefix, using independently audited Value observation consistency and String content-key premises. Native namespace/cache/set and File adapters, pre-append normalization and the full locked transaction remain open.

`journal_recovery::Apply` checks JSON event-list structure and reconstructs transactions in raw-frame order. `journal_state::State` resets partial recovery, confirms matching boundaries and quarantines uncertain append. This does not prove complete Coordinator event application or outer Journal file/run binding.

`request::{lookup,response,copy_field,remember}` are actual verified receipt functions. `request_history` proves idempotence and preservation for admitted histories; native request key/hash, admission, authorization and complete business/cross-log recovery remain separate obligations. The [formal scope](FORMAL_VERIFICATION.md) records exact current inputs, regression evidence and trusted library laws.

`Coordinator::apply` now delegates six consumer/batch/checkpoint/retention branches and their final request receipt to actual verified `queue_metadata::apply`. Its View is the exact sequence of nested JSON edits; success applies the full plan, while error describes the applied prefix and first invalid path. `json_update::update` proves exact leaf effects and unchanged state for invalid paths under audited Map/Clone library contracts. Native branch selection, partial-state quarantine, remaining events, scheduler caches and complete replay/cross-log composition remain caller obligations.

`journal_append` connects actual queue validation/serialization to State/Writer append. `journal_equivalence` connects the resulting frame to successful byte/JSON replay and preserves finite-history observations under the same raw prefix. It does not establish complete business replay, parser acceptance, physical prefix selection, native File mapping or run-identity comparison.

The multi-queue/request `cross_log` induction now establishes a combined **durable-effect model** invariant. Its conditional connection to actual `catalog_state::eligible` explicitly requires root correspondence from the locked native snapshot. It does not prove that Coordinator/CommitIo/BatchIo, namespace mapping, closure caches or lower WAL recovery generate these histories; the source entry points above remain responsible for that refinement.


## Abstract durable effects and remaining refinement

The following covers every action of `cross_log::Action`. The corresponding TLA+ models use the same classes of durable effects, with their per-model environment contracts recorded in the registry. A listed lower proof does not establish the enclosing native action. WAL-fragment projection in `DurableHandoff` is proved separately; its connection to this combined model is still open.
